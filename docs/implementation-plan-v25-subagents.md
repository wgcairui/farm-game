# v25 视觉修复实施计划与 Subagent 分工

本文件是执行计划，不代表已实施或已验收。此次仅新增计划文档，不修改生成器、不覆盖现有截图、不提交或推送 Git。

### 当前状态与证据边界

- V01、V03 在原计划中记录为关闭，后续仍需回归。
- V02、V04、V05 的代码已有修复，不能按旧文档描述直接重复修改，也不能直接标记视觉通过。
- 当前 `clock_panel` 约束盒右边为 690，并有右侧 1.1px 描边补偿；690 + 1.1 < 692，不能仅凭旧记录再次认定裁切并继续左移。实际绘制坐标、滤镜与截图仍需核对。
- 烟囱已有 back/contact/smoke 分层；是否正确穿过屋面，需要检查实际遮挡，不以函数名称证明通过。
- 现有报告记录四种宽度下 13 个命中目标通过。脚本只报告超过较小目标面积 6% 的重叠，因此不等于严格零重叠。
- `audit()` 的局部描边补偿不是自动测量所有 SVG 可见轮廓，更不能证明所有滤镜、遮挡及材质正确。
- 原实施文档存在滞后，必须以当前实现与本轮证据同步状态。

## 2. 固定约束

1. 不覆盖 v24 基线生成器、页面和图像；禁止恢复参考截图作为背景。
2. 保持连续 4×6 地块、8 格耕地与 16 格草地区分，不为修复装饰而缩小或移动网格。
3. 保留独立命中层，正常主页维持 13 个语义目标，每个至少 44×44 CSS px。
4. 不恢复底部 ID/version，不用相似度分数替代视觉验收。
5. v25 未通过验收前，不宣称美术冻结或 Cocos 正式接入完成。
6. 尊重现有暂存区与用户修改，不 reset、不批量重新暂存、不自动 commit/push。

## 3. Subagent 编组及文件所有权

主 agent 负责调度、整合、浏览器交互验证和最终结论。主 agent 不在写入型 subagent 工作期间修改其文件。

| 角色 | 类型 | 工作范围 | 写入权限 |
|---|---|---|---|
| S1 视觉实现 | general-purpose | 按阶段处理 V01–V12；同步布局与命中配置 | 仅 `design-preview/gen_v25.py` |
| S2 验证工程 | general-purpose | 强化命中检查、状态参数与验证报告，修正脚本说明 | `design-preview/validate_hits.py`、`design-preview/render.py`；必要的新测试文件须先由主 agent 指定路径 |
| S3 代码审查 | code-reviewer | 独立检查当前差异、绘制顺序、坐标一致性及验证盲点 | 只读 |
| S4 文档同步 | general-purpose | 根据已完成阶段的证据更新计划、场景规范与集成边界 | 主 agent 明确指定的 docs 文件；不修改源码或截图 |
| 主 agent | 主会话 | 保存基线清单、执行统一生成、浏览器测试、截图复验、汇总验收 | 整合产物、验收报告、必要的 Git 忽略规则；避开在写文件 |

### 并行原则

- S1 与 S2 可并行，因为写入文件不同；两者先约定 DOM 状态和命令行参数，再改相关接口。
- S3 可与实现并行做初步只读检查；最终审查必须针对写入完成后的固定快照，运行期间暂停修改。
- S4 只在阶段证据确定后写入，不根据口头进度或代码注释提前勾选完成。
- V02/V04/V05 同属建筑和右侧功能区，必须由同一个 S1 联动处理。
- V08、V09、V06/V11/V10、V07/V12 虽可分别研究，但目前共享生成器，不允许多 agent 并发写入。
- 不为并行而先重构生成器成模块。若未来确有必要，另设独立重构任务和等价渲染回归。
- 浏览器工作由主 agent 执行，不委派给 subagent。游戏页面不是文档/海报/图表，不使用 document judge；由主 agent 按浏览器工具规范观察游戏画面。

## 4. 阶段与执行顺序

### P0：建立可复现基线与证据契约

负责人：主 agent；S2 可同步检查验证器。

工作：
1. 记录 Git 状态及当前暂存差异，不改变暂存状态。
2. 记录 v24 基线和 v25 源文件哈希；保存执行前产物，避免重生成覆盖唯一证据。
3. 建立独立运行目录，例如 `design-preview/review-v25/<run-id>/`，集中存放本轮截图、JSON 与报告；不要自动全部纳入版本控制。
4. 确认生成器输出参数、渲染路径与验证器默认报告路径。现有脚本未提供隔离输出时，由 S2 先增加可选输出目录并保持旧命令兼容。
5. 约定普通/引导状态标识、目标名称与目标数预期。建议使用显式 `data-state` 和 `data-target`，由 S1/S2 在实现前确定；本计划不假定现有接口已经存在。

交付：运行目录、文件哈希清单、参数契约和初始问题表。

关卡：能够识别“哪个源码快照生成了哪份报告”。

### P1：空间结构复验与修补（V01–V05）

负责人：S1；S2 并行增强检查；主 agent 视觉复验。

工作：
- 先复验当前实现，再针对真实失败点修改，避免重复实施旧问题。
- V02：核对草屋/狗屋墙面、屋顶、屋檐、落地点和阴影是否与土地的 2:1 dimetric 方向一致；仅增加侧面不构成验收。
- V04：核对时间绘制坐标、LAYOUT、描边及滤镜边界，确认不破坏建筑轮廓与功能列间隔。
- V05：核对烟囱后段被屋面合理遮挡、接缝沿屋面成立、烟雾不被误遮挡；清理未使用参数或误导性注释。
- V01/V03：回归栅栏不跨土地顶面、柱脚落地，以及远山/远林/草坡/近景的层次。
- 对栅栏/土地与时间/建筑的关键轮廓关系增加可复现检查。若只能实现粗略多边形，明确其近似边界，并保留视觉复验，不能冒充精确 SVG 几何检测。

交付：全图、建筑/烟囱/右栏局部图、审计日志及逐项判定。

关卡：所有高优先级问题均有实际画面证据通过；否则留在本阶段修补。通过后冻结空间布局，不冻结全部美术。

### P2：地块与主要材质（V08 → V09）

负责人：S1，单写者串行执行。

- V08：修改 `build_plot()` 的材质表现，减少厚边和重复内圈高光，增加适量草皮边缘与接触阴影；不改网格几何。
- V09：调整建筑屋顶、树冠、篮子纹理；茅草成束、树冠成团、编织跟随曲面，不用均匀颗粒替代体积。
- 改动树冠与屋顶时回归 P1 的林带缺口、建筑轮廓和烟囱接缝。

交付：材质前后局部对比及四宽度整体图。

关卡：草地/土壤可区分、无坐垫感，移动端材质不糊成噪点，空间结构无退化。

### P3：功能图标与引导（V06、V11、V10）

负责人：S1；S2 根据约定补充状态检查。

- V06：重画商城横向雨棚和门面、公益掌心与托举剪影，统一标签重量。
- V11：强化仓库、装扮、好友入口的功能线索，保留合理导航尺寸。
- V10：普通状态不显示手套；引导状态指向一个明确目标，手套不截获无关触摸。
- 主 agent 遮住标签检查图标语义；这属于内部识别复验，不声称代表真实用户测试。
- 分别记录静态状态、触摸路由和业务行为。尚未接通的业务按钮明确标为未实现，不因命中层存在而视为完成。

交付：普通/引导状态、遮文字图标对照、两种状态的命中与触摸路由结果。

关卡：普通状态无手套，引导目标明确；命中层与实际视觉目标对应，无引导遮挡导致的误触。

### P4：装饰和底部收尾（V07、V12）

负责人：S1。

- V07：花朵调整为疏密不同的小簇；石板改变形状和角度，补充草地嵌入关系。
- V12：弱化底部宽波带，用低对比草丛与局部阴影过渡。
- 保持土地外围安静区域，不新增装饰遮挡来掩盖结构问题。

交付：完整候选图与装饰前后局部对比。

关卡：土地与建筑保持主次，底部融入草地，未新增无意义文字或密集装饰。

### P5：最终回归、审查与文档同步

负责人：主 agent；S3 审查；随后 S4 更新文档。

1. 冻结待验收源码快照，统一生成产物。
2. 执行结构、关键轮廓、命中、状态与浏览器回归。
3. S3 审查生成器与验证脚本的实际差异，报告有证据的缺陷，不替代画面验收。
4. 主 agent 观察 692/375/390/430px 普通/引导画面，检查文字可读性、长文本、裁切、遮挡和语义。
5. 有失败则返回对应负责人修复，并重验受影响项目及完整回归；报告中保留失败和修复轨迹。
6. S4 同步原问题计划、实际采用的场景规范和必要的集成说明；明确历史规范与当前候选的关系，不把 v24 历史证据重写成 v25 证据。
7. 更新来源、尺寸、锚点、落地点、图层、倍率及版本清单后，才允许正式美术冻结。

交付：最终候选、验证 JSON、复验表、审查结论和同步后的文档。

Cocos 正式接入是本计划通过后的下一阶段。网页通过不替代 Cocos 安全区、坐标、触摸和实机验证。

## 5. 验证标准与命令

以下现有命令均从仓库根目录执行；运行前先保存现有证据。传入完整仓库相对路径，避免默认当前目录引起找不到 HTML。

```bash
python3 design-preview/gen_v25.py --audit
python3 design-preview/gen_v25.py design-preview/farm-v25.html
python3 design-preview/render.py design-preview/farm-v25.html design-preview/final-v25.png 692
python3 design-preview/render.py design-preview/farm-v25.html design-preview/mobile-v25-375.png 375
python3 design-preview/render.py design-preview/farm-v25.html design-preview/mobile-v25-390.png 390
python3 design-preview/render.py design-preview/farm-v25.html design-preview/mobile-v25-430.png 430
python3 design-preview/validate_hits.py design-preview/farm-v25.html
```

隔离输出与双状态命令由 S2 实现并验证后写入最终报告；不把尚未实现的参数作为可运行命令交付。涉及浏览器的执行和观察遵守主会话已加载的浏览器工具规范。

### S2 必须补充的验证能力

- 对目标数量、唯一语义标识和预期目标集合进行断言，防止零目标也通过。
- 显式区分旧版 >6% 重叠检查与新验收标准：报告所有正面积交集，数值舍入误差如需容忍，必须单列阈值和实际值。
- 不仅检查固定 1500px 视口，还检查目标是否超出舞台、页面是否横向溢出。
- 普通/引导状态独立记录，验证引导装饰不会截获目标触摸。
- 验证失败返回非零退出码，并保留机器可读详情。
- 报告记录源码/HTML 哈希、状态、视口、运行时间和输出路径，避免旧报告冒充本轮证据。
- 修正验证脚本中“render.py 仅截 SVG”等滞后说明；实际渲染器已截取 `#stage`。
- 为缺少目标、重复目标、越界、微小重叠、非法状态等增加失败用例；明确工具运行通过和视觉通过是两个结论。

### 最终验收矩阵

| 维度 | 覆盖 | 通过条件 |
|---|---|---|
| 结构 | XML、引用、布局、选定关键轮廓 | 无非法引用、越界或未解释冲突 |
| 视觉 | 4 个宽度 × 2 种状态 | 无主要轮廓破坏，材质和图标语义清楚 |
| 命中 | 目标集合、尺寸、越界、交集 | 预期 13 个语义目标、每个至少 44×44 CSS px、无实际命中冲突 |
| 文字 | 常规与长文本 | 可读，无截断关键含义或遮挡功能 |
| 引导 | 普通/引导切换 | 普通无手套，引导指向正确且不截获无关触摸 |
| 业务 | 已实现的按钮行为 | 单独记录真实行为；未接通项不得冒充通过 |
| 基线 | v24 哈希、网格几何 | 未覆盖历史基线，土地邻接与分区不变 |

## 6. 每次派单模板

所有写入型 subagent 的派单必须包含：

```text
目标：本阶段要关闭的 V 编号和验收条件。
起点：当前源码快照、已通过项、已知失败证据。
允许修改：明确的绝对文件路径；未列出的文件不得写入。
禁止：覆盖 v24、修改其他 agent 文件、浏览器操作、git add/commit/push、扩大范围重构。
接口：需要保留或新增的 DOM/CLI 约定。
验证：可自行运行的非浏览器检查；浏览器相关验证交主 agent 执行。
返回：改动摘要、文件/函数位置、检查命令及结果、未解决问题、需要主 agent 复验的画面区域。
状态：只能声称已实现或实际检查通过，不自行宣称最终视觉验收。
```

S3 的派单额外要求：针对固定快照只读审查，输出问题、位置、触发条件和证据；无发现时明确审查范围与限制。

S4 的派单额外要求：每个完成状态必须引用对应运行记录和截图路径；不得将缺失证据写成通过。

## 7. 推荐启动批次

1. **主 agent 完成 P0；并行启动 S1（P1）与 S2（验证工程）。**
2. **主 agent 复验 P1，S3 审查稳定快照；失败则返回 S1/S2。**
3. **S1 顺序完成 P2 → P3 → P4，每阶段主 agent 复验后才进入下一阶段。** S2 可在独立文件上继续补充验证，但接口调整须先同步。
4. **P5 固定快照后并行进行主 agent 浏览器复验与 S3 只读审查；两者通过后再启动 S4。**
5. **主 agent 汇总最终交付与残留问题。** Git 提交/推送和 Cocos 正式实现不在本次计划的自动执行范围。

首个里程碑仅为“v25 空间结构通过复验且文档与实现一致”；后续里程碑依次为材质、功能语义与引导、装饰收尾、最终回归与资源冻结。采用关卡制，不承诺未经验证的工期。
