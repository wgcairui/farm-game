## 3. 实施顺序与交付关卡

### A. 空间结构修正（V01–V05）

- 从 `gen_v24.py` 建立后续候选版本，保留 v24 图像作为复审基线，不覆盖后冒充原版证据。
- 栅栏、建筑、树林、右侧功能区先做整体构图；其中 V02 建筑轮廓与 V04/V05 必须联合确定。
- 交付候选全图及上述区域局部图，与参考图并排检查。
- 关卡：所有高优先级项有画面证据确认关闭，才能冻结相应布局。

### B. 材质、图标与收尾（V06–V12）

- 先统一明暗、描边、材质和标签规范，再处理花石板等小装饰。
- V08 只能改地块表现，不重新推导或移动已成立的连续网格。
- V10 交付普通/引导两个状态；V11 做遮文字识别复核。
- 关卡：完整画面无新增遮挡，图标语义清楚；不以相似度分数抵消视觉缺陷。

### C. 工程回归与视觉复验

- 为候选版本同步更新 `LAYOUT`、允许重叠列表、装饰保留区、视觉节点和命中区，不能只改坐标表而不改画面。
- 单独检测栅栏与土地顶面、时间与建筑主要轮廓；现有道具/道具豁免及时间/草屋白名单不能作为放行理由。涉及精确多边形的检查属于后续待新增功能，不声称现有审计已具备。
- 执行候选生成器的 XML/引用/布局审计，再用实际浏览器验证 692/375/390/430px。
- 各宽度记录完整画面、文字可读性、无横向溢出、每个操作目标至少 44×44 CSS 屏幕像素、无命中区重叠/越界，以及普通/引导状态。
- 高 DPI 只能改善清晰度，不能解决字号过小。关键 HUD 需独立字号与长文本测试。
- 交付复验表：问题编号、修复版本、截图路径、复验结论、剩余问题。只有实际观察过的项目可以标完成。

### D. 资源冻结与 Cocos 接入

- A–C 通过后才能冻结正式美术；可在此前并行做灰盒、存档与种植流程，不把占位素材视为最终资源。
- 按独立场景对象、地块、作物、HUD 导出资源，记录来源、尺寸、锚点、落地点、图层、倍率及版本；不能把整张参考截图或整页 UI 当成游戏底图。
- 具体导入、坐标映射、安全区、命中层和客户端验证见 [Cocos 集成指南](./cocos-integration.md)。
- 正式客户端必须重新验收，网页静态渲染和触控区记录不能替代 Cocos 实机验证。

## 6. 已知审计缺口

- `audit()` 检查 `LAYOUT` 名义包围盒是否越界，**未计算描边和滤镜扩张**——时钟胶囊右侧 1.1px 被裁切即由该缺口漏检。
- `audit()` 不核对栅栏/地块顶面、时钟/建筑轮廓的精确多边形交叠——计划 §3.C 要求"待新增"。
- `audit()` 不测量命中区——完全依赖 `validate_hits.py`。
