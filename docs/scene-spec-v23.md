## 一、画布与投影

| 项 | 值 | 说明 |
|---|---|---|
| 画布 | `692 × 1218` | 与参考图 1:1，比例 1:1.76（iPhone 竖屏） |
| 设计单位 | px（1× 逻辑像素） | 渲染时 `device-scale-factor=1` |
| 投影 | **2:1 dimetric** | 世界坐标 → 屏幕：`x' = (i−j)·w/2`，`y' = (i+j)·h/2`，`h = w/2` |

**关键澄清**：游戏美术里说的 "2.5D 等距" 实际是 **dimetric**（二测投影），
轴角 `arctan(1/2) ≈ 26.565°`，不是真等距的 30°。判断依据：
对参考图做 FFT 自相关，得到的晶格向量是 `(47, +24)` 与 `(−47, +24)`，
其长度为 `√(47²+24²) = 52.8`，两向量完全对称 —— 对应瓦片外接盒
`94 × 48`，横竖比正好 2:1。

## 四、草地图层：颗粒滤镜（本版最关键的技术点）

草地/土壤的可信度几乎完全取决于**颗粒纹理**。写法有对错之分：

### ❌ 错误写法

```xml
<rect fill="#ffffff" filter="url(#grain)" opacity="0.5"/>
```

白底矩形 + 滤镜输出的是**不透明的浅灰**，等于给整个地面盖一层半透明白纱。
实测后果：草地蓝通道被抬高 40+（参考图 B=99 → 输出 B=146），
综合分反而卡在 **90.98%**。

### ✅ 正确写法（真 multiply）

```xml
<filter id="grainGrass" x="0" y="0" width="100%" height="100%">
  <feTurbulence type="fractalNoise" baseFrequency="0.85" numOctaves="4"
                seed="17" stitchTiles="stitch" result="n"/>
  <feColorMatrix in="n" type="saturate" values="0" result="g"/>
  <feComponentTransfer in="g" result="gc">
    <feFuncR type="table" tableValues="0.90 1"/>
    <feFuncG type="table" tableValues="0.90 1"/>
    <feFuncB type="table" tableValues="0.90 1"/>
    <feFuncA type="table" tableValues="1 1"/>
  </feComponentTransfer>
  <feComposite in="gc" in2="SourceGraphic" operator="in" result="clip"/>
  <feBlend in="SourceGraphic" in2="clip" mode="multiply"/>
</filter>
```

并把**整个草地图层组**（渐变 + 亮斑 + 暗斑）包进 `<g filter="url(#grainGrass)">`。
颗粒只做 0–10% 的微暗抖动，不改变色相。

**单此一项：90.98% → 93.18%（+2.20）。**

土壤颗粒用同样结构，`baseFrequency="0.5"`、`tableValues="0.80 1"`（更粗更深）。

## 五、地块系统

### 5.1 几何参数

```
床顶点   T0 = (393, 589)
格向量   U  = (47, +24)      # 右下
         V  = (-47, +24)     # 左下
网格     4 (沿 U) × 6 (沿 V) = 24 格
瓦片外接盒 94 × 48   (2:1 dimetric)
```

第 `(i, j)` 格的**中心**：

```
C(i, j) = T0 + i·U + j·V + (U + V)/2
        = ( 393 + 47·(i − j) ,  613 + 24·(i + j) )
```

床的四个角：`T0`、`T0+4U = (581,685)`、`T0+4U+6V = (299,829)`、`T0+6V = (111,733)`。

### 5.2 「连续，不角对角」的正确做法

用户明确指出过"地块应该是连续的，而不是角对角"。正确理解是：

- 瓦片按**完整格**布置，相邻格中心距**恰好等于格向量本身**（横向 94、纵向 48）→ 天然边-边共享。
- 瓦片**顶面**以格中心为基准缩放 `0.88`，只是留出参考图里那条约 11px 的榃色缝隙，
  **不改变拓扑**。缩放值调大调小只会让缝隙变窄变宽，永远不会让瓦片变成角对角。
- 之前 v18 的错误是：瓦片高 46 但行距用了 49（多 3px）→ 相邻行只在角上碰到。

### 5.3 格的两种状态

| 状态 | 位置 | 数量 | 表现 |
|---|---|---|---|
| 已耕（褐色） | `j ∈ {0, 1}` | 8 格 | 褐色土面 + 1 株幼苗 |
| 未耕（草绿） | `j ∈ {2, 3, 4, 5}` | 16 格 | 亮草绿顶面，无作物 |

> `j=0` 是最靠后的一排（右上），`j` 增大方向朝左下。即**已耕地块位于床的右上角**
> ——这是从参考图逐格统计出来的（每格菱形内褐色/绿色像素占比）。

### 5.4 针叶松比例

参考图实测针叶松 **宽/高 ≈ 0.37–0.45**，早期用 `w = h * 0.60` 画出来是"胖圆锥"。
`pine()` 现为 `w = h * 0.46`，五层锥体（顶宽比 0.32 / 0.45 / 0.58 / 0.71 / 0.86）。
另在 `mid-trees` 组放了 6 株 h=126–180 的中景大树，对应参考图中央那几株最显眼的松树。

### 5.5 幼苗

每格 1 株，尺寸在 `0.92–1.22` 之间微调（`(i+j) % 3` 决定），
锚点在格中心偏下 3px。结构：短茎 → 两片贴茎子叶 → 两片顶芽。
整体高度约 15px（×0.92 ≈ 14px），与参考图的幼苗尺度一致。

增加株数的扩展方式：`build_plot()` 里对 `(i, j)` 循环时按 `crop_level` 选择绘制
不同生长阶段的 sprite（对应 Cocos 侧 `assets/sprites/crops/` 的 4 阶段序列帧）。

### 6.6 图标返工踩过的三个坑

1. **SVG 路径里的 `{f(x):}` 空格式说明符不报错，但会吞掉逗号**。
   `f'L{f(a):}{f(b)}'` 生成的是 `L2.1-1.2` 而不是 `L2.1,-1.2` —— 整条五角星路径
   渲染成空白，排查了很久。多坐标点必须显式写逗号。
2. **多行字符串拼接被单行替换打断**。`o.append('...'` 换行接 `+ rect(...)` 的写法，
   用正则/子串替换很容易加上一个多余的 `)`，导致 `IndentationError`。
   改图标时优先用**行号区间替换**，不要用子串匹配。
3. **替换函数体时会把夹在中间的模块级常量一起删掉**。
   本版 `DECOR_BLOCK` 被 `layer_basket` 的整段替换吞掉过两次。
   替换 `def A(): ... def B():` 之间的内容前，先确认中间没有别的东西。

## 七、装饰物自动避让

花草草簇是随机撒的，最容易"长到"道具身上（实测出现过花瓣盖住干草车、
草簇横穿标牌）。做法是在生成时维护一张保留区表：

```python
DECOR_BLOCK = [
    (92, 566, 604, 852),   # 地块床
    (416, 382, 618, 572),  # 草屋
    (296, 458, 418, 562),  # 狗屋 + 食盆
    (186, 492, 268, 618),  # 木牌
    (0, 434, 258, 560),    # 池塘 + 池边栅栏
    (0, 540, 72, 674),     # 干草车
    (286, 828, 398, 942),  # 一键务农
    (0, 0, 692, 292),      # 顶部 HUD
    (0, 946, 692, 1218),   # 底部 UI
    (592, 392, 690, 468),  # 提篮
    (40, 700, 268, 830),   # 左下栅栏
]
```

撒点循环里 `if in_block(x, y, pad=4): continue`，最多重试 150 次取有效点。
新增道具时**必须同步往 `DECOR_BLOCK` 加一行**，否则装饰会重新长上去。

## 八、布局审计

规范里最容易失守的不是风格而是**对齐**。生成器内置两个自检命令：

```bash
python3 design-preview/gen_v23.py --audit    # 越界 / 压盖检查, 有问题退出码=1
python3 design-preview/gen_v23.py --layout   # 导出元素坐标表 (markdown)
```

`--audit` 的规则：

1. 所有元素包围盒必须在 `0 ≤ x ≤ 692`、`0 ≤ y ≤ 1218` 内；
2. `hud` 类元素之间重叠面积不得超过较小者的 **6%**（描边级接触放行）；
3. 判定为设计意图的压盖，在 `LAYOUT` 表里用 `allow_overlap` 白名单显式声明。

最近一次运行结果：**33 个元素，无越界、无意外压盖**。

> 实际抓到的问题举例：`hand_cursor` 与 `nav_pet` 重叠 18% —— 手套指针的下缘
> 压到了"宠物"按钮上。修正方式是整体上移 16px。这类问题肉眼在缩略图上几乎看不出来，
> 但有坐标表就能稳定拦下来。

## 九、生成器工作流

`gen_v23.py` 是**程序化 SVG 生成器**（不是手写 SVG），所有坐标、色值、

### 9.1 随机种子

树林、草丛、石子路都用固定种子（`20260910 / 7 / 31 / 99`），
保证每次生成结果完全一致 —— 否则每次微调都会让整片树林重新排布，
无法做 A/B 对比。

### 9.2 调参入口

| 想改什么 | 改哪里 |
|---|---|
| 瓦片大小 / 缝隙宽度 | `TILE_SCALE`（0.88）、`TILE_R`（圆角 9） |
| 地块位置 | `T0`、`U`、`V` |
| 已耕 / 未耕分布 | `build_plot()` 里的 `dirt = j <= 1` |
| 树林疏密 / 轮廓 | `layer_forest()` 的 `top_profile(x)` 与三层循环的 `range(N)` |
| 针叶松胖瘦 | `pine()` 的 `w = h * 0.46`（参考实测 w/h ≈ 0.37–0.45，早期 0.60 太胖） |
| 中景大树 | `layer_forest()` 的 `mid-trees` 组（参考图中央 3 株显眼针叶松） |
| 草地色调 | `build_defs()` 里的 `grassGrad` |
| UI 位置 | `layer_ui()`，改完跑 `--layout` 同步文档 |

## 十、移植到 Cocos Creator

场景是"预渲染 sprite 堆叠"结构，与 Cocos 的 2D 节点树天然对应：

| 设计稿图层 | Cocos 节点 | 资源 |
|---|---|---|
| L4 草地 | `Sprite` + `TiledMap`（或用单张大图） | `assets/sprites/scene/grass.png` |
| L7 瓦片 | 每个格一个 `Sprite`，`position = C(i,j)` | `assets/sprites/plots/{grass,dirt}.png` |
| L7 作物 | 每个格一个子 `Sprite`，`zIndex = 格 y 排序` | `assets/sprites/crops/crop_XXX_0N.png` |
| L8 草屋 / L8b 狗屋 | 单 `Sprite` | `assets/sprites/buildings/*.png` |
| L11 UI | `Canvas` 下的独立节点树 | `assets/sprites/ui/*.png` |

**关键**：瓦片用 `C(i,j) = (393 + 47(i−j), 613 + 24(i+j))` 直接算，
不要手摆。作物按 y 排序设 `zIndex` 即可得到正确的前后遮挡。

出图建议：把 `gen_v23.py` 的每个图层单独导出成 PNG（`--layers` 扩展即可），
比在 Cocos 里重画省事，也保证与设计稿像素级一致。

## 十二、已知限制

1. **山/林带 MAE 45 已是该方法的上限**。参考图是手绘密林，每根枝条都有笔触；
   矢量三角/圆无法逐枝匹配。继续加密树木反而会让分数回落。
2. **底部 UI MAE 43 同理**。参考图头像是照片级角色立绘（写实渲染），
   SVG 只能做风格化的近似。若要真正对齐，需外包美术绘制立绘。
3. **矢量细节存在边际递减**：每加一处细节都是"我画 A、参考图是 B"，
   92.9–93.2 大致是这套方法的天花板。想再上一个台阶需要换手段
   （手绘位图贴图 / 逐像素风格迁移），而不是继续调参。
4. **本文档的分区数值来自 `final-v23.png`**，改动生成器后请重新出图并更新本节。
